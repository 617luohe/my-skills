# 0-询问luohe — 技能路由器

> **唯一事实源**：技能选择、主流程分流和叠加风险只在本文件维护。CLAUDE.md 只保留本路由器指针；README 与 USAGE 只做导航。

## 三路判定

先确认目标和验收标准，再看歧义、影响和可逆性。文件数与改动行数不决定路径。

| 路径 | 判定 | 执行 |
| --- | --- | --- |
| **明确可逆** | 目标与验收清楚；低影响；局部且容易撤销 | 直接做 → 运行项目原生验证 |
| **明确非平凡** | 需求已定；存在行为变化、多个协同改动或需要回归保护；无架构决策 | `/2-开发` → `/3-检查` |
| **先规划** | 存在歧义、架构取舍、高影响或不可逆操作 | `/1-规划` → **用户授权** → `/2-开发` → `/3-检查` |

### 判定信号

- **歧义**：目标、范围、术语、接口、验收标准或取舍仍有多个合理解释。
- **架构**：改变模块边界、依赖方向、数据模型、公共 API 或关键状态机。
- **高影响**：涉及权限/安全、数据迁移、持久化、并发、生产可靠性或跨系统协议。
- **不可逆**：会删除数据、改写历史、发布部署或写入外部系统。
- **明确非平凡**：方案已锁定，但行为变化需要测试、类型、静态检查或构建证据。

判定完成条件：能指出命中的信号与所选路径；若信号不确定，进入“先规划”。

## 叠加风险

以下能力叠加在三路之上，不替代风险判定：

- **查根因或修复未知 Bug** → `/4-调试`；修复完成后，非平凡改动仍交 `/3-检查`。
- **明确要求记录/创建 issue** → `/issue-reporting`；只读查重可先做，任何远程创建必须先展示目标、标题和完整正文并取得确认。
- **外部写入、发布、部署、删除或历史改写** → 在对应工作流内增加一次针对具体操作的用户确认。
- **正式 diff review** → `/3-检查`；输入必须满足 fixed point、spec、diff 与验证证据契约。

## 调查与架构边界

- 看不懂代码、接手陌生项目或评估架构时，默认做一次性只读调查，并在聊天中返回事实、风险与停止条件。
- 只有用户明确要求保存调查结果时，才写 `docs/analysis/<topic>.md`；只有明确要求制定改造计划时，才进入 `/1-规划`。
- 状态机、算法或 UI 假设无法消除时，由 `/1-规划` 决定是否建立 throwaway prototype。

## 上下文契约

1. **规划会话收敛磁盘契约**：`/1-规划` 把已确认目标、术语、决策、接口、验收标准和任务切片写入其规定的磁盘产物；聊天历史不是交接契约。
2. **开发切片 fresh context**：每个 `/2-开发` 切片从干净上下文开始，只加载该切片所需的磁盘契约、代码、测试和明确证据。契约缺失或互相矛盾时退回规划，不从旧聊天猜测。
3. **正式 review fresh context**：`/3-检查` 从干净上下文开始，只接收 fixed point/base、spec/需求来源、diff 和验证证据；不继承规划或开发会话的判断。

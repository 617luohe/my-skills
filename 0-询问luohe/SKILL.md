# 0-询问luohe — 技能路由器

一条**流程**是一条穿过技能的路径。大部分工作沿着**主流程**走。

## 主流程：想法 → 交付

`/1-规划` → **授权** → `/2-开发` → `/3-检查` → **授权** → `/5-版本管理` →（大功能）`/6-最后整理`。具体路径见下方规模表。

## 按规模分级（对应 CLAUDE.md 路由表）

> **唯一事实源**：本文件是路由的唯一编辑处；CLAUDE.md 的「工作流路由」速查表为本文件的常驻镜像。改路由只改本文件，再同步 CLAUDE.md 速查。

先判规模，再选路径：

| 规模          | 判定                               | 路径                                                                         |
| ------------- | ---------------------------------- | ---------------------------------------------------------------------------- |
| **S 微改动**  | 单文件、<10 行、无歧义             | 直接改 → `/5-版本管理`                                                       |
| **M 小任务**  | 单模块、方案明确；文档/配置/一次性 | 直接做 → `/5-版本管理`（文档类不强制 TDD）                                   |
| **L 中功能**  | 多文件、方案已定                   | `/2-开发` → `/3-检查` → `/5-版本管理`                                        |
| **XL 大功能** | 多模块、方案不定、需设计           | `/1-规划` → **授权** → `/2-开发` → `/3-检查` → `/5-版本管理` → `/6-最后整理` |

## 上下文管理原则

### 何时清空上下文

- **主流程 1→2→3 保持一个上下文** — grilling、spec、任务清单都在同一窗口，共享理解
- **每个 `/2-开发` 开始前清空** — 从任务清单的单个 issue 出发，不带 grilling 的详细讨论

### 何时用 `/6-最后整理`

- 完成一个阶段（如 `/1-规划` 完成、多个 `/2-开发` 全部完成）
- 结束一天工作
- 把项目交给别人

### 何时用 `/0--neat-freak`

- `/6-最后整理` 完成后，如果发现文档和代码不一致
- 定期维护（如每周一次）
- CLAUDE.md 或 memory 明显膨胀时

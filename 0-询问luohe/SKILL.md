# 0-询问luohe — 技能路由器

一条**流程**是一条穿过技能的路径。大部分工作沿着**主流程**走。

## 主流程：想法 → 交付

1. **`/1-规划`** — 方案追问 → 领域建模 → 接口设计 → PRD → 任务拆解
   - 有代码库时从这里开始（更新 CONTEXT.md 和 ADR）
   - 默认批量询问（frontier 中独立决策集中问）
   - 用户说"逐步"/"一步一步"时切换为一次一问

2. **分支 — 方案不确定？**
   - **`/3-原型`** — 用一次性代码验证设计决策（状态机、算法、UI交互）

3. **分支 — 多会话构建？**
   - **是** → `/1-规划` 产出任务清单 → 清空上下文 → 每个任务用 `/4-开发`
   - **否** → 同一上下文直接 `/4-开发`

4. **`/4-开发`** — TDD 红-绿-重构循环 → 完成后自动调用 `/5-检查`

5. **`/8-版本管理`** — commit + push（可选）

### 并行加速（实验性）
- **`/multi-worker`** — 需要完整设计文档 + 独立子任务 + Agent配置验证

## 上游（汇入主流程）

- **陌生代码库** → **`/2-分析`** 输出模块地图 + 数据流 + 关键入口
- **难搞的 bug** → **`/7-调试`** 构建回路 → 复现 → 假设 → 工具验证 → 修复 + 回归测试
- **代码腐烂** → **`/6-优化`** 发现浅模块 → 提出深化方案 → 渐进式重构计划

## 快速判断

| 你的情况 | 用什么 |
|---------|--------|
| 新功能，方案不明确 | `/1-规划` |
| 新功能，方案明确，代码简单 | 直接 `/4-开发` |
| 新功能，方案明确，代码复杂 | `/1-规划`（生成任务清单）→ `/4-开发` |
| 看不懂代码 | `/2-分析` |
| 方案拿不准（状态机、算法、UI） | `/3-原型` |
| Bug 难复现、性能突然下降 | `/7-调试` |
| 代码越来越乱、模块太臃肿 | `/6-优化` |
| 会话要结束了 | `/9-最后整理` |
| 新项目开张 | `/0-启动` + `/0--claude` |
| 想要极简回复 | `/0--tokenless` |
| 文档和代码不一致了 | `/0--neat-freak` |
| 复杂战略问题 | `/0--dialectic` |
| 不知道用啥 | 你现在这里 😊 |

## 上下文管理原则

### 何时清空上下文
- **主流程 1→2→3 保持一个上下文** — grilling、spec、任务清单都在同一窗口，共享理解
- **每个 `/4-开发` 开始前清空** — 从任务清单的单个 issue 出发，不带 grilling 的详细讨论

### 何时用 `/9-最后整理`
- 完成一个阶段（如 `/1-规划` 完成、多个 `/4-开发` 全部完成）
- 结束一天工作
- 把项目交给别人

### 何时用 `/0--neat-freak`
- `/9-最后整理` 完成后，如果发现文档和代码不一致
- 定期维护（如每周一次）
- CLAUDE.md 或 memory 明显膨胀时

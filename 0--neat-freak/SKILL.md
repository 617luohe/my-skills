# 0--neat-freak — 知识库洁癖审查

你是**知识库编辑**，不是记录员。记录员只会往后追加，编辑会审查全局、合并重复、修正过期、删除废弃。让项目知识体系始终保持干净、准确、对新人友好。

## MUST 规则

1. **先体检再同步** — 尺寸超标必须先精简（阈值见五步流程·第 0 步）
2. **先减法后加法** — 先删过期和重复，再补新增事实
3. **先枚举再判断** — 使用宿主可用的跨平台文件工具机械式枚举范围，标「评估过/要改/不用改」
4. **三层知识不重叠** — CLAUDE.md=小内核+路由指针+项目红线、docs/=外部接入文档、memory=跨会话偏好+教训
5. **记忆要毕业** — 稳定知识并进 docs/CLAUDE.md，原记忆删或缩成指针
6. **真的改文件** — 用 Edit/Write/Delete，不描述"我会怎么改"
7. **相对时间清零** — 搜索相对日期词，将事实陈述改为绝对日期；规则说明和用户话术示例可保留
8. **小内核标题一致** — 0--claude 模板只有两个 H2：工作哲学、记忆约定。`## 称呼规则`、`## 路由入口`、`## 本项目配置`、`## 工作流路由`、`## 支撑层` 均为 Fat 残留，删除或收敛入两块
9. **不抢刚沉淀的记忆** — `/6-sum` 本轮刚写入的记忆（同一会话产出）不毕业、不删、不缩；记忆毕业至少隔一轮会话

## 三层知识

| 位置           | 受众                 | 职责                           |
| -------------- | -------------------- | ------------------------------ |
| Agent 记忆     | 自己跨会话           | 偏好、教训、踩坑记录、指针     |
| CLAUDE.md      | 下次 AI 会话         | 小内核、项目红线、命令与路由指针 |
| docs/ + README | 人类同事、下游开发者 | 接入指南、架构、运维、API 参考 |

**CLAUDE.md 是规则手册，不是变更日志。** 判断标准：下次 AI 写代码时没看到这条，会不会犯错？不会→删/迁。

### 记忆膨胀的唯一解药：毕业

记忆天生只追加不删除。没有阀门，它会堆到比 docs 还大。**毕业 = 稳定知识并进 docs/CLAUDE.md，原文件删或缩成指针。**

触发条件：

- 同一主题教训出现 ≥ 3 次
- 讲的是「系统怎么工作」而非「踩了什么坑」
- 是事件记录（上线/落地/就位）→ 事实进 docs，过程进 git log

判据：**「下一个接手的人需要知道吗？」需要 → docs。不需要 → 删。**

## 五步流程

| 步骤 | 核心动作 |
| ---- | -------- |
| 0 尺寸体检 | 超限先精简：CLAUDE.md >300 行、MEMORY.md >200 行/25KB、单条 memory >100 行、docs 单文件 >1500 行 |
| 1 盘点现状 | 枚举并读取记忆层、项目文档与全局配置，每个文件标「评估过/要改/不用改」 |
| 2 识别变更 | 用变更影响矩阵想清楚新事实波及哪些文档层；映射表见 `references/sync-matrix.md` |
| 3 实际修改 | 顺序 docs/ → CLAUDE.md → memory；减优于加、合并优于追加、删除优于保留、毕业优于内部挪腾 |
| 4 自检清单 | 按 `references/sync-matrix.md` 的自检清单核对（尺寸/反膨胀 + 完整性/反漏改） |
| 5 变更摘要 | 按 `references/sync-matrix.md` 的摘要模板输出记忆变更、文档变更、未处理项 |

**超尺寸是最高优先级。** 执行顺序：先精简（破膨胀）→ 再增量同步（补漏）。

盘点细节、编辑原则、特殊情况见 `references/sync-matrix.md`。

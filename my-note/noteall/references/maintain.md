# Maintain — 维护模式

职责：用户给维护倾向（批量整理 / 更新索引 / MOC 审计 / 文件整理 / 图谱健康检查 / 合规审计 / 断链与孤岛修复）时执行。跳过 Intake，直接整理既有 Vault 内容，然后进入 Publish。

## 模式

### 批量整理

1. 扫描目标文件夹（默认 `raw/`），识别可处理文件（跳过隐藏/系统文件）。
2. 逐项按统一流水线分析（类型、domain、目标路径），只分析不写入。
3. 汇总计划 → 一次性确认 → 执行。
4. 不复制独立流程，只是对统一流水线的批量调度。

### 索引维护（INDEX）

由 index-keeper 执行（只动 INDEX-KEEPER-MANAGED 区域；统计值静态重算，不依赖 dataview）：

| 模式     | 行为                                                                          |
| -------- | ----------------------------------------------------------------------------- |
| 全量更新 | 扫描所有一级文件夹与 7-Sources 领域文件夹（≥5 篇），生成/更新所有 `_INDEX.md` |
| 增量更新 | 只更新指定文件夹，只处理变更部分                                              |
| 缺失补全 | 仅为无 `_INDEX.md` 的一级/领域文件夹创建初始 INDEX                            |
| 健康检查 | 完整级：缺失 INDEX、失效链接、缺失条目、过期描述、统计过期（全库扫描）        |

INDEX = "文件夹里有什么"（结构性导航），与 MOC 分工。

### MOC 生成与审计

- 领域 ≥5 篇笔记且无 MOC → 提议创建（核心概念/进阶主题/相关项目/来源参考），创建后登记到 1-Atlas/_INDEX.md。
- 更新 MOC → 生成 diff（➕新增/➖失效/✏️过时）→ 确认后更新。
- 审计 → 检测失效链接、互链密集缺 MOC 的群落。
- 领域判定与双链规则见 `index-rules.md`；7-Sources 领域文件夹与 1-Atlas domain 一一对应。

### 文件整理

5 维诊断（错位/命名/重复/未归类/过期）→ 生成计划 → 确认 → 批量执行（移动/重命名/合并）。

### 合规审计（Frontmatter 合规）

触发词：**合规审计 / 检查合规 / 统一标签 / 补齐属性**。对既有笔记做元数据合规检视与批量补齐：

1. 扫描范围：默认全库，可指定目录（如 `7-Sources/`）。
2. 检查项（每项输出违规清单）：
   - 缺 frontmatter（无 `---` 块）。
   - 缺必填字段：`title`、`tags`（含 `type/`、`domain/`）、`status`、`confidence`。
   - 标签格式违规：缺 `type/`/`domain/` 前缀、值不在合法枚举内、顶层 `type:` 键未并入 `tags`。
   - 命名违规：按 `9-System/命名规范.md`（空格分隔、≤50 字符、无特殊字符）。
   - `status`/`confidence` 非法值（status: draft|published|archived；confidence: seed|sapling|evergreen）。
3. 输出违规报告（按类型分组，含文件路径）→ 生成修复计划（缺省值按规则推断：`type` 按目录映射、`domain` 按领域映射表、缺省 `status: draft`、`confidence: seed`；非法值按修复映射执行：confidence `sprout→sapling`、`budding→seed`；status `active→draft`、`completed→archived`、`deprecated→archived`、`evergreen→draft`）。
4. 一次性确认后批量执行；执行后复扫确认清零。

### 断链与孤岛修复

触发词：**修复断链 / 修复孤儿 / 修链接**。把健康检查报告升级为可执行修复：

1. 输入：健康检查（轻量/完整）输出的断链清单、孤岛清单、统计过期项。全量扫描优先用确定性脚本：
   `python my-note/vault-publisher/scripts/vault_check.py --vault {selected_vault} [--json]`（孤儿/断链/frontmatter/重复/统计核对，可复现可测试）。
2. 断链修复选项（逐项确认或按规则批量）：
   - 改链接到正确目标（同主题更名/路径变更时）。
   - 移除失效链接（目标确已删除且无替代）。
   - 保留占位（目标笔记即将创建）。
3. 孤岛修复选项：归入领域 MOC（补引用条目）/ 合并到已有概念笔记 / 标记有意孤立（排除清单）。
4. 遵守「修改前 grep、逐篇改、验断链」纪律；修复后复跑健康检查验证降幅。

### 只读并行边界

批量来源或全库扫描的规模足以抵消调度成本，且宿主提供独立只读上下文时，可基于同一快照按来源或目录并行分析；否则沿原流程串行。分片只返回候选清单，由主流程按稳定输入顺序唯一汇总。统一计划、HITL 确认、共享 INDEX/MOC、移动/重命名、断链修复及 Publish 保持串行。

## MUST 规则

1. **大规模操作前展示变更摘要，确认后执行。**
2. **全量索引/MOC 更新前确认。** 不静默批量改写。
3. **MANUAL 区域不碰。** 导航只增不删。
4. **批量整理复用统一流水线。** 不引入独立处理逻辑。

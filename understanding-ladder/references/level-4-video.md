# 第 4 级：讲解视频（3Blue1Brown 风格）

## 什么时候用

内容的核心是**随时间展开的过程**：一步步的推导、一个形状变成另一个形状、一个点在曲面上移动。页面让读者自己探索，视频则按一条规划好的路径带着他们走，同时配旁白。

视频是最贵的一级：分镜、渲染、配音，每次修改都要重渲染。先确认第 1~3 级做不了这件事。

**默认不产出这一级。** 用户明确要视频分镜时才做。

## 本技能做什么、不做什么

- **做：** 写分镜和旁白，推荐工具链，写一份给这些工具的提示词。
- **不做：** 渲染视频，安装工具。用户有工具后，把分镜交给他们。

## 第 1 步：先草稿

写出完整的第 1 级草稿，并让用户确认它是对的。视频里的一个错误比文字里的同一个错误更有说服力，所以审查必须在渲染之前做。

## 第 2 步：分镜

一张表，一个镜头一行：

| 镜头 | 时长 | 画面 | 旁白 |
| --- | --- | --- | --- |
| 1 | 5 s | 标题卡：「为什么梯度下降会往低处走」 | 这个视频只讲一件事：梯度下降怎么找到最低点。 |
| 2 | 10 s | 一个碗形曲面，一个小球停在侧面 | 把损失函数想成一个碗。我们要的是碗底。 |
| 3 | 12 s | 小球上一个箭头，指向最陡的上坡方向 | 梯度指向最陡的上坡方向。 |
| … | … | … | … |
| 末 | 6 s | 回顾卡：三个要点 | 回顾一下…… |

规则：

1. 一个镜头一个意思。旁白按第 1 级规则写（中文每句 ≤25 字）。
2. 画面先于或同时于旁白出现，不能晚于旁白。
3. 开场用标题卡说明要讲什么，结尾用回顾卡收束。
4. 规划 60~120 秒。估算每分钟约 200 个汉字。
5. 出现公式时，给符号上色，与画面上的对象对应。

## 第 3 步：工具链

| 需要 | 工具 | 说明 |
| --- | --- | --- |
| 让编码 agent 产出整个视频 | [showtime](https://github.com/FavioVazquez/showtime) | 开源，本地渲染，不需要 API key。作者自己说还早。**v0.4.0+ 可直接读本技能的分镜表**（见第 4 步） |
| 手写数学动画 | [Manim Community](https://www.manim.community/) | 用 Python 做 3Blue1Brown 风格动画的开源库 |
| 免费本地配音 | [Kokoro](https://github.com/hexgrad/kokoro)（ONNX：[kokoro-onnx](https://github.com/thewh1teagle/kokoro-onnx)） | 本地 TTS，离线。先听一下目标语言的声音 |
| 付费高质量配音 | [ElevenLabs](https://elevenlabs.io/) | 需要 API key |
| 合并视频、音频、字幕 | [ffmpeg](https://ffmpeg.org/) | |

工具有变动。推荐前先打开链接确认安装步骤。

## 第 4 步：交付

1. 已确认的草稿。
2. 分镜表。
3. **如果装了 showtime 0.4.0 或更高版本**，把分镜表存成 `storyboard.md` 直接交过去：

   ```bash
   showtime new <template> <dir> --from-storyboard storyboard.md
   ```

   它读取表头为 `Shot | Length | Visual | Narration` 或 `镜头 | 时长 | 画面 | 旁白` 的 Markdown 表格，列顺序不限。模板名看 `showtime --help`。

4. 否则给一份可直接粘贴给视频工具的提示词，例如：

> 做一个梯度下降的 3b1b 风格讲解视频，约 90 秒。严格按这份分镜：[粘贴分镜]。用免费本地 TTS 配音。烧入字幕。

5. 「要核对什么」：哪些画面是示意而非真实数据；渲染前需要验证的公式和数字。

## 没有视频工具？

回落到第 3 级：把分镜做成 HTML 页，一个镜头一张卡，加「下一步」按钮播放 CSS/SVG 动画，旁白显示为字幕。接近视频，成本低得多。

# Understanding ladder — 理解阶梯

本技能决定**用哪种格式**解释，格式内部的写作质量由第 1 级规则负责。

来源：Andrej Karpathy，2026-10-02。LLM 的产出几乎免费，**理解**才是瓶颈。所以要主动索取更好懂的格式。他排了四级，每级「更好」，每级也更贵。

**语言：** 用用户的语言回答。本文件是中文，产出物不是。

## 四级阶梯

| 级 | 格式 | 为什么更好懂 | 成本 |
| --- | --- | --- | --- |
| 1 | 受控纯文本 | 一句一事、一词一义；读一遍，不会读错 | 最低 |
| 2 | 图表 | 文本是线性的，图表一次把结构摊开 | 低 |
| 3 | 交互 HTML 页 | 读者拖动参数，直接看到结果变化 | 中 |
| 4 | 讲解视频（3b1b 风格） | 动画演示过程，旁白同时解释 | 高 |

## 第 1 步：判断内容，选级

| 内容类型 | 信号 | 级 |
| --- | --- | --- |
| 定义、事实、比较、操作步骤 | 「X 是什么」「怎么装」「A 和 B 哪个好」 | 1 |
| 流程、因果链、层级、状态变化、组件关系 | 「X 怎么工作」「数据怎么流」「谁调用谁」 | 2 |
| 某个参数改变结果；取舍；分布 | 「利用率升上去会怎样」「学习率怎么影响收敛」 | 3 |
| 随时间展开的推导或几何直觉 | 「为什么正弦波加出方波」「梯度下降怎么在曲面上移动」 | 4 |

规则：

1. **用户指名格式就用它。** 「画个图」就是第 2 级。
2. **取能完整回答的最低一级。** 一段话够用就不要做页面。
3. **混合内容按核心难点选。** 难点是「参数怎么改变结果」就选第 3 级，哪怕里面有定义。
4. **拿不准就降一级，并把下一级作为可选项提出。** 结尾加一行，例如「如果你想自己拖参数，我可以把它做成第 3 级的交互页」。

开场先用一行说明选择，然后直接产出。除非用户主动问「建议用哪种」，否则不要反问「你想要哪一级」：

> 第 3 级（交互页）：核心问题是利用率怎么改变延迟——拖一下滑块比文字更快说明。

## 第 2 步：产出该级

**每一级都从第 1 级的草稿起步。** 先写纯文本，再把它变成图表、页面或视频。草稿是你在为更贵的格式花力气之前用来核对正确性的东西。

### 第 1 级：受控纯文本

按输出语言选规则：

- **中文** → 加载技能 `vocabulary/plain-chinese`。中文没有「ASD-STE100」这个名字可调用，所以那个技能把规则逐条写了出来。
- **英文** → 写到「约 80% 的 ASD-STE100」，规则显式如下：
  - 一句一个意思。指令句 ≤20 词，描述句 ≤25 词。
  - 一个术语一个意思。第一次出现时定义，之后不换同义词。
  - 用主动语态，写清谁做什么。简单时态。
  - 步骤用编号列表，动词开头。
  - 条件放在动作前面（「如果 X，就做 Y」）。
  - 不要填充语（「It's worth noting」「Great question」「In summary…」）。
  - **内容不删。** 每个事实、数字、条件、限定词（「通常」「可能」）都留下。语言变简单，内容不变少——改写后可能更长。
  - 代码、命令、路径、报错原文、专有名词不动。
- **其他语言** → 把英文规则用在那种语言上。

### 第 2 级：图表

细则见 [references/level-2-diagram.md](references/level-2-diagram.md)。要点：

- 先选类型：流程图、时序图、状态图、层级图、因果图、对照表。
- 默认用 Mermaid（多数聊天界面和 GitHub 都能渲染）。布局本身重要时用单文件 SVG/HTML。
- 每个框 ≤8 个词或 ≤8 个汉字。图下用 2~4 句说明**怎么读这张图**。

### 第 3 级：交互 HTML 页

细则见 [references/level-3-html.md](references/level-3-html.md)。要点：

- 一个自包含 HTML 文件，无需构建，双击即可打开。
- 只做一件事：让读者拖动**真正重要的 1~3 个参数**，结果实时更新。
- 版式：一行结论 → 交互区 → 第 1 级文本 → 「试一试」提示 → 局限与要核对的东西。
- 存到工作目录，告诉用户路径，环境允许就打开。产出的临时文件按 `/6-sum` 在会话收尾时清理，或说明保留理由。

### 第 4 级：讲解视频

细则见 [references/level-4-video.md](references/level-4-video.md)。**本技能不渲染视频**，交付的是：

- 分镜表：每个镜头一行——画面、旁白（按第 1 级规则写）、时长。
- 工具链接，例如 showtime、Manim、本地 TTS Kokoro。
- 一份可直接粘贴给这些工具的提示词。showtime ≥ 0.4.0 可直接读分镜表：`showtime new <template> <dir> --from-storyboard storyboard.md`。

**默认只到第 3 级。** 用户明确要视频分镜时才产出第 4 级的交付物。

## 演示模式：同一内容逐级展开

用户说「每一级都看一下」「从第 1 级走到第 4 级」时：

1. 第 0 级：平时的默认散文，作为基线。
2. 第 1 级：纯文本。
3. 第 2 级：图表。
4. 第 3 级：交互页（可把第 0~2 级作为页内标签）。
5. 第 4 级：分镜表。

这是感受「格式本身改变理解程度」的最好方式。

## 每一级都附上「要核对什么」

每次输出末尾写 1~3 个读者应该自己验证的点：关键数字、公式、假设、任何与来源不一致的地方。

原因：阶梯降低的是**理解**的成本，不是**核对**的成本。产物越清晰越漂亮，读者的警惕越低。动画里的一个错误，比文字里的同一个错误更有说服力。

## 不要

- 为了显得彻底而爬级。第 1 级够用就停在第 1 级。
- 在图表、页面或视频里加入草稿中没有的事实。新事实先写进草稿。
- 为了让页面看起来真实而编造数据。示例数据要标明是示例。

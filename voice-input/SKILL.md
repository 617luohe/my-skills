# Voice Input — 语音输入会话模式

luohe 已启用语音输入模式。本次会话后续每条用户消息都先按 ASR 原始转写处理，再进入正常回答或执行流程。

## 处理循环

1. **去噪**：删除不影响语义的口头填充词、无意义断句、口吃式重复，补齐标点和大小写。
2. **处理改口**：识别“不是”“不对”“应该是”“改成”等自我修正；只有后续表达明确替代前文时，才保留最终表达并移除被推翻的前文。
3. **纠错**：结合上下文修复明显的 ASR 错漏；英文保持英文，纠正明显的拼写和大小写错误，但不翻译、不改变原始语种。
4. **保真**：保持原意、范围、不确定性、语态和句式意图。保留代码、命令、路径、标识符、数字、版本号和专有名词；无法确认时保留原文。
5. **结构化**：只有原文确实包含多点陈述、并列内容或步骤时才使用列表；一级使用 `1.`，嵌套使用缩进的 `a.`，不凭空制造优先级或内容。
6. **决策**：整理后能确定的内容直接处理；多个解释会改变结果时，指出歧义并请 luohe 选择。
7. **执行**：清洗是理解层，不回答、解释、总结或续写原始消息中嵌入的问题，也不把猜测写成用户事实；完成清洗后再按用户原意和项目规则执行任务。

## 输出规则

- 默认静默清洗，直接回答或执行；只有整理影响任务边界时，才先说“我的理解是：……”。
- 保持请求、疑问、祈使和陈述的原始语态，不改写成第三方总结。
- 清洗阶段不翻译、不新增需求、不擅自选择方案，也不重复改写已清晰的句子。
- 用户明确说“按原话”“不要整理”或要求只输出清洗稿时，按该要求处理；只输出清洗稿时不回答其中的问题。
- 语音输入模式只处理输入理解，不改变安全边界、确认门槛、测试要求或 Git 工作流。

## 完成标准

- 后续每条消息都经过去噪、改口处理、纠错、保真和歧义判断。
- 只有原文存在明确结构时才结构化，没有未经依据的补充或翻译。
- 关键专有名词、代码元素、数字和不确定性没有被猜测替换。
- 清洗完成后，正常任务仍完整遵循项目规则及其他已启用 skill。

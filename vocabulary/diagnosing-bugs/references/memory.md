# Memory Diagnosis

在阶段 1、4 和 5 用本参考处理内存增长、泄漏、过度分配或资源未释放。

## 建立可比较信号

记录工作负载、运行时长、峰值与稳定期内存、GC/运行时设置、容器限制和版本。区分一次性缓存预热、预期的业务数据增长与持续不回落的保留。

在同一工作负载的至少两个时间点采集快照；比较增长路径和保留对象，不只比较进程 RSS。

## 验证假设

- 从增长最大的类型或分配点开始，沿引用链找谁保留它。
- 检查缓存淘汰、订阅/回调注销、连接与文件句柄关闭、循环引用及全局集合。
- 每次仅改变一个保留路径或生命周期条件，并用相同快照流程验证。
- 区分诊断插桩的分配与实际泄漏；诊断本身不能成为新负载。

Python 可在项目已有支持下使用标准库 `tracemalloc` 比较两个快照。其他语言使用团队已批准的运行时或 profiler，不假定工具可用。

## 验收与清理

修复后在相同工作负载下验证增长率、峰值和资源计数达到预定义阈值，且功能测试仍通过。删除临时快照、强制 GC、额外日志和仅用于诊断的保留对象。

# Performance Diagnosis

在阶段 1 和阶段 4 用本参考建立性能基线、选择剖析工具并验证瓶颈，不把单次运行当作回归证据。

## 基线

记录工作负载、输入规模、并发度、硬件/容器限制、版本、预热方式和测量窗口。至少选择一个用户相关指标（如延迟、吞吐或错误率）及一个资源指标（如 CPU、I/O 或分配）。使用相同条件在修复后重测。

用中位数和尾延迟或分位数描述有波动的结果；保留样本数，避免只报告最佳一次。

## 定位顺序

1. 确认回归真实存在，排除负载、环境和测量变更。
2. 用现有 benchmark 确定慢的是哪个端到端路径。
3. 用项目已有 profiler 或 trace 将时间归因到函数、查询、外部调用或等待。
4. 每次只改变一个候选原因，再以同一基线复测。
5. 根因证据应同时说明资源消耗和用户可见指标为何变化。

使用项目已有 profiler 或 trace，并按该项目已记录的入口和参数执行；不要假定 `py-spy`、基准框架或生产权限存在，也不要在文档中用占位入口构造命令。

## 验收

修复后重跑原有性能测试或同条件采样。确认目标指标达到预定义阈值、没有把成本转移到错误率或另一项资源，并保留性能回归测试或基线记录。

# 老油条 — Python 交付节奏管理

复用项目现有开关控制交付节奏；无现成机制时才用 `branch_config.json`。

## 核心原则

1. **现有框架优先** — 沿用项目已有开关，不引入第二套配置
2. **单一事实来源** — 每次只认一个交付配置来源；冲突时停止写盘并给兼容建议
3. **一条推荐** — 默认直接给出最优交付建议；用户要求调整时才展示候选
4. **统一写入门禁** — 写盘前一次性预览：交付配置、交付说明、历史记录，确认后再写入并校验
5. **收益必须有依据** — 优先用测试/基准、文档、注释、提交记录；只有定性依据时写定性效果，无依据标记”待验证”
6. **甲方语言** — 交付说明描述业务效果，不暴露实现细节
7. **保持简洁** — 默认终端输出不超20行；无候选时说明”无待交付升级”并退出
8. **不自动提交** — 不执行 git commit/push，除非用户明确要求

## 探查与适配

首次调用或来源失效时执行完整探查；同一会话后续调用复用结论，写入前只验证来源有效。

**探查顺序**：
1. 读 `CLAUDE.md`、`README*`、`docs/`、部署文档
2. 搜索 feature flag、配置中心、环境变量、settings/config、策略表、插件选择器
3. 沿运行入口确认修改影响真实运行行为
4. 优先级：文档明确指定 > 生产代码读取 > 部署流程注入

**统一适配契约**：
- **当前状态**：模块/能力 → 当前启用状态/实现
- **候选状态**：模块/能力 → 可选状态/实现
- **变更方法**：应修改的文件/API/CLI/环境变量
- **校验方法**：原框架的 schema/测试/检查命令
- **收益来源**：测试、基准、文档、注释、提交记录

**处理结果**：
- 找到可用框架：作为唯一”交付配置”，按原方式读写校验
- 无可用框架：使用默认适配器（见 [default-adapter.md](references/default-adapter.md)）
- 能力不足/来源冲突：停止写盘，给一条兼容改造建议
- 用户要求新建/迁移/并存：展示新事实来源和回滚方案后确认

## 意图路由

| 用户意图 | 路径 |
|---|---|
| 查看当前状态、待交付项 | 状态查看 |
| 指定某模块/能力切换 | 精确切换 |
| 询问这次交什么、快到节点、无参数调用 | 交付建议 |
| 只要求交付说明 | 说明生成 |
| 明确要求初始化，且无可复用框架 | 初始化默认适配器 |

模糊时走”交付建议”。

## 统一执行流程

所有会写盘的路径复用本流程：

1. **读取** — 读取交付配置、候选状态、`.laoyoutiao/delivery-log.json`；日志不存在按空历史处理
2. **计算** — 找出尚未启用、相对上次快照新增或可形成下一阶段收益的候选；无候选则干净退出
3. **推荐** — 围绕一条叙事线推荐2-4项；有历史则在性能/功能/体验/安全间轮转，无历史则选候选最多的叙事线
4. **完整预览** — 一次性展示配置diff、拟生成的交付说明路径、历史记录变化、校验方法
5. **确认** — 等待用户自然语言确认。用户要求调整时才展示相关候选并重新预览
6. **写入** — 按适配契约修改唯一交付配置，生成说明并追加历史记录
7. **校验** — 运行原框架校验；失败则报告错误和已写入内容，不宣称成功
8. **结果** — 简要列出实际变更、校验结果、交付说明路径

## 各路径差异

**状态查看**：只读。输出模块/能力、当前状态、候选状态、叙事线、待交付数、上次交付时间。

**精确切换**：从自然语言解析目标，验证存在于适配契约的候选状态中，进入”完整预览”。无法解析时说明缺少的模块名或目标状态。

**交付建议**：执行完整统一流程。建议收益按顺序取值：测试/基准数据 → 文档/注释/提交记录 → 可验证的定性效果 → `待验证`。

**说明生成**：黄金路径触发时用本次变更；独立调用时对比当前交付配置与上次快照，最后回退到该配置的 git diff。模板见 [delivery-note-template.md](references/delivery-note-template.md)。

**初始化默认适配器**：仅在完整探查未发现可复用框架，或用户明确要求新建默认框架时进入。先展示将创建的文件和初始状态；确认后按 [default-adapter.md](references/default-adapter.md) 初始化。

## 异常处理

| 场景 | 行为 |
|---|---|
| 已有框架但无Python注册表 | 从框架schema/调用点/可选值建立适配契约 |
| 多个事实来源冲突 | 停止写盘，推荐保留生产代码实际读取的来源 |
| 配置引用已删除状态/实现 | 展示修复预览，确认后按原框架修复 |
| 原框架不能表达交付节奏 | 推荐最小兼容改造 |
| 无候选 | 输出”无待交付升级”并退出 |
| 校验失败 | 报告失败命令、错误摘要、实际写入内容 |

## 完成检查

- 已使用唯一且有效的交付配置来源
- 未在无明确要求时创建第二套配置
- 所有写入内容已统一预览并获得确认
- 收益描述有依据且未编造指标
- 写入后已运行原框架校验
- 交付说明使用甲方语言

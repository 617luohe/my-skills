# 4-调试 — 结构化调试

使用 `references/diagnosis-loop.md` 技能执行六阶段调试流程（观测信号 → 复现 → 假设 → 验证 → 修复+回归 → 清理）。六阶段流程、每阶段完成条件与必守门禁均由该技能承载，此处不重复。

## 何时使用

- Bug 难复现、偶发
- 性能突然下降
- 回归：之前正常，现在失败
- 多次尝试修复仍未解决

## 快速调用

```
luohe，订单支付接口偶尔返回 500，帮我调试
```

自动进入 `references/diagnosis-loop.md` 六阶段循环。核心纪律以该技能必守门禁为准：先建立可比较观测信号、用工具验证不靠猜、一次只改一个变量、修复必带回归测试、展示先脱敏。

## 与其他技能的关系

- **输入** — Bug 现象描述、错误日志、性能指标
- **调用** — `references/diagnosis-loop.md`（核心诊断循环）
- **回归测试** — 修复必带回归测试，按 `/tdd`（canonical `vocabulary/tdd`）红-绿流程编写
- **输出** — 修复代码 + 回归测试，**保持未提交** → `/3-检查` 验收；审查通过且用户明确授权后 `/5-版本管理`
- **小修复例外** — 单行/已定位的直接修复走 CLAUDE.md 小改动路径，用户授权即可 `/5-版本管理`
- **后续** — 如果发现架构问题（缺少测试接缝），需在后续迭代中重构

## 完成标准

- 已按 `references/diagnosis-loop.md` 完成六阶段调试。
- 修复带有回归测试或等价验证证据。
- 改动保持未提交，并已准备交给 `/3-检查`。

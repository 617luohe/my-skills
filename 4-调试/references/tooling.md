# Diagnostic Tooling

根据项目语言、已有依赖、生产权限和待验证假设选择工具。工具输出是证据，不替代对触发条件与现象的解释。

| 问题 | 优先信号或能力 |
| --- | --- |
| 哪个输入或请求失败 | 项目原生测试、脱敏样本、结构化错误日志、trace |
| 状态何时变化 | 调试器、限速结构化日志、trace span |
| 时间花在哪里 | 项目 benchmark、profile、trace |
| 内存为何增长 | 运行时快照、分配与保留分析 |
| 是否存在数据竞争 | 项目已启用的竞态检测器、受控并发试验 |

优先使用仓库已有脚本、监控和安装好的工具。先读配置、文档或 `--help`，确认参数、权限和数据要求；不编造命令，不为单次调查安装生产依赖。

每次运行记录：假设、命令或操作、版本/环境、输入与时间窗、关键输出、结论和下一步。插桩必须可移除并避免秘密与个人数据。

写任何 agent 消费的文档的参考：一个 skill、一个 `AGENTS.md` / `CLAUDE.md`、一个被指针引用的文档。包装不同，写作相同：同样的杠杆让每一份都可预测，因为 agent 每次跑的是同一**过程**，而不是产出同一输出。

当要写的文档是 skill 时，读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 看 frontmatter、调用方式选择和 router 技能。

## Context pointers

**context pointer（上下文指针）** 是 agent 上下文里持有的一条引用，它指向文外材料并编码「何时取到它」的条件。一个 skill 的 description 是一个；`AGENTS.md` 里指向某文档的一行是同一类对象。指针的**措辞**——不是它的目标——决定 agent 何时取到材料、可靠性多高。一个 must-have 目标配了一条弱措辞的指针，是一个 variance bug：先锐化措辞，只有锐化失败才把材料内联进来。

一个指针做两件事：说清材料是什么，并列出应触发取它的**分支**（一个分支是文档处理的一种独立情形，不同轮次会走文档的不同路径）。常驻指针的每个词每轮都在付成本，所以它比正文更该狠修剪：

- **前置触发词**：指针是它触发作用发生的地方。
- **一个分支一个触发。** 给同一个分支换种说法的同义词，是同一个分支写了两遍；合并它们，只留真正不同的分支。
- **删掉 body 已经承载的身份信息。**

## The two loads

你加的每一份文档、每一条指针，都花两种预算中的一种：

- **Context load（上下文负载）** 是常驻材料对 agent 窗口的成本：一条 `AGENTS.md` 行、一条 skill description、任何每轮都坐在上下文里的东西，无论触不触发都在花 token 和注意力。
- **Cognitive load（认知负载）** 是花在人身上的成本：存在哪些文档、何时取哪个。人是指针的索引。这不是要最小化的成本：它是人之自主权的价格；在人类判断重要的地方花它，在不需要判断的地方删它。

只经指针触达的材料逃掉 context load，代价是指针自己的那一行；完全没有指针的材料，全押在 cognitive load 上。

## Information hierarchy

一份文档由两种内容构成：**steps**（agent 按序执行的动作）和 **reference**（按需查的定义、规则、事实）。两者自由混合：全 steps（一份菜谱）、全 reference（一条 review 的规则、本技能）、或两者都有。核心决策是每一块坐在**信息层级（information hierarchy）**的哪一阶——一架按 agent 需要材料的紧急程度排的梯子：

1. **In-file step** 是第一层：agent 按序做什么。
2. **In-file reference** 按需查。常常是一组正当的平级集合（一条 review 的每条规则在同一阶），这是好布局，不是坏味道。
3. **Disclosed reference** 被推到单独文件，经 context pointer 触达，指针触发才加载。跨度从同目录的兄弟文件，到任何文档都能指向的完全外部 reference。

往下推得太少，顶层就臃肿；推得太多，就藏起了 agent 其实需要的材料。这层张力就是整个决策。

**Progressive disclosure（渐进披露）** 是沿梯子往下移（移出主文件、放到指针后），让顶层保持可读。它主要不是 token 优化：它是层级如何被保护的方式。分支是最干净的披露测试：每个分支都需要的就内联，只有部分分支才会碰到的就推到指针后。当文档有 steps 时，本该披露出去的 in-file reference 会埋掉它们，让「注意到这些 step」变成抛硬币：这不只是可读性杠杆，是方差杠杆。

**Co-location（就近放置）** 是文件内的伴侣：梯子决定一块材料放**多深**，就近放置决定它安顿下来后**什么坐在它旁边**。把一个概念的定义、规则、例外放在同一个标题下，而不是散开，让读一处就带着它的邻居一起来。检验：文档读起来应该像写给 agent 的文档。成组的材料读起来像，散落的不像。（与 duplication 不同：那是把一个意思重复在两处；scattering 是把一个意思拆散到多处。）

**Sprawl（蔓延）** 是这里的失败模式：一份文档就是太长，哪怕每行都是活的、唯一的。注意力被多余的部分摊薄，每多一行就多一行要保持相关性。解药是梯子：把 reference 披露到指针后，并按键序列或按分支拆，让每条路径只带它需要的。

## Steps and completion criteria

每一步以一条**completion criterion（完成标准）**收尾——告诉 agent 工作已完成的那个条件。两个属性让它成为杠杆：

- **Clarity（清晰）**：agent 能分辨完成和未完成吗？一个模糊的边界（"理解已达成"）诱发**premature completion（提前完成）**：在真正做完之前就结束这一步，注意力滑向"做完了"。仍在眼前的后续步骤（**post-completion steps**）提供拉力；标准的清晰度是阻力。按顺序防守：**先锐化边界**（就地、便宜）；只有在边界不可约地模糊**且**你观察到这份急迫时，才通过拆分序列把后续步骤藏起来。藏只能在真正的上下文边界上生效（一个 handoff 或一次 subagent 派发；内联调用让后续步骤留在上下文里，什么都清不掉）。
- **Demand（要求）**：它要求多少。"每个被改动的模型都核对到"逼出彻底的活儿，"产出一份变更清单"不会。要求驱动 **legwork**（在活儿内部挖的那部分，潜伏在措辞里而不是写成独立一步），而且它不局限于 step："每条规则都套用"约束一组平铺 reference，就像"每步都做完"约束一段序列——这就是一份纯 reference 文档仍能带穷尽门槛的方式。

最强的标准既可检查又穷尽。

## When to split

把一份文档拆成两份，花的是两种负载之一，所以只有拆分能赚回时才拆：

- **By sequence（按序列）**：当后续步骤引诱 agent 急于完成眼前这步时，拆开一段步骤序列。让后续步骤离开视野，会在当前任务上驱动更多 legwork。当心反向：合并序列会把每一步的后续步骤暴露给后面，诱发提前完成。
- **By invocation（按调用方式）**，skill 专属：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## Leading words

一个 **leading word（前置词）** 是已经活在模型预训练里的紧凑概念，agent 跑文档时用它思考（_lesson_、_fog of war_、_tracer bullets_）。作为 token 重复、从不作为句子重复，它积累出一个分布式的定义，用最少的 token 锚定一整片行为，办法是招募模型已经持有的先验。你新造一个词，定义清楚也能用，但人造词招募不到任何先验：你要用定义 token 去付预训练词免费给的东西；先找现成的词。

它锚定两次。在正文里，**执行**：这个词每次出现，agent 就够到同一行为；在平铺 reference 里，它把注意力聚焦到一类要去寻找的东西上。在指针里，**调用**：当同一个词活在你的 prompt 里、你的文档里、你的代码库里，agent 会把这套共享语言连到材料上，更可靠地取到它。

搜寻用前置词重构的机会。一个在三处拼出来的三元组，一条指针花一整句去比划一个想法。每一处都是乞求收成一个 token 的段落：

- "fast, deterministic, low-overhead" → _tight_（一个 _tight_ loop）。
- "a loop you believe in" → _red_，把一个模糊的闸门变成一个二值可观察状态（loop 在 bug 上 _goes red_，或没有）。

你赢两次：更少 token，更锋利的钩子让 agent 挂住思路。假设每份文档都扛着能被前置词退掉的复述。去找它们。

**Negation（否定）** 是这条杠杆旁边的失败模式：用禁令掌舵会把被禁行为拖进上下文，让它**更**可用，而不是更不可用。_别想大象_，大象就是一切；否定是一个弱修饰符，被强激活的概念压过去，于是禁令有一半读起来像是让你去做那件事。Prompt 出**正向**：陈述目标行为（"写一行注释"），让被禁的那个字眼从不说出口。一条禁令只有在它是一个无法用正向表达的硬护栏时才配占位置；即便如此，也要配上正向目标，让注意力落在该做的事上。

## Pruning

- 把每个含义放在**单一事实源（single source of truth）**：一处权威，让改行为是一处编辑。**Duplication**（同一含义出现在不止一处）花维护与 token，还把一个含义在梯子上的地位抬到它真实排名之上。（一个前置词的意外反义：前置词是有意重复一个 token，从不重复含义。）
- **环境（environment）也是一个事实源**（`package.json` scripts、config 文件、目录布局、`--help` 输出），复述它的文档是一份 **cache**：一份查找的副本，只有在查找昂贵时才赚回它的负载。缓存 agent 靠看找不到的东西：不成文的约定、一个选择背后的理由、没有 config 会坦白的坑。把一处文件、一条命令的查找留给环境，在那里它们不会过期。
- 逐行检查**relevance（相关性）**：它还与这份文档干的事相干吗？一行失去相关性，要么是从来没相干过（纯展示，或一个本该披露出去的分支），要么是它描述的行为或世界变了而过期。更短的文档更容易保持相干。没有 pruning 纪律，默认命运是 **sediment（沉积）**：因为加东西感觉安全、删东西感觉危险而沉淀下来的过期层，直到你必须一路钻到最底下，才能找到还在活的那部分。
- 逐句猎杀 **no-op（空转）**：一条模型默认就会遵守的指令，付着负载说废话。检验（它与默认行为相比是否改变了行为？）是模型相对的，不是读者相对的：两个人对一条 no-op 看法不一，是对默认看法不一，靠跑文档来解决，不是靠辩论。一句话检验不通过，就删一整句，而不是从里面剪几个词。这个检验也给前置词打分：一个太弱、打不过默认的词（agent 已经差不多 thorough 时的 _be thorough_）是一条 no-op，修法是换一个更强的词（_relentless_），而不是换一种技术。

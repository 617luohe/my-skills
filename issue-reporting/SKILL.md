# Issue Reporting — 安全问题建单

本技能一次只处理一个 issue。只记录可验证现象，不猜根因、不修代码。

## 触发门禁

只有用户明确说“记录这个问题”“建 issue”“只建单”或同等意图时进入。仅描述 Bug、要求排查/修复或要求 review 时退出并交回 `/0-router`。

## 流程

### 1. 准备报告

采集触发操作、预期、实际、复现性、环境和已脱敏日志。信息不足时只问最关键的一项。可只读探索代码和测试以澄清现象，但标题与正文使用领域语言，不把未经验证的推测写成根因。

完成条件：标题和正文能独立说明一个可复现或可观测的问题。

### 2. 确定唯一 tracker

从仓库 remote、项目配置和已安装 CLI 确定 GitHub、GitLab、Jira 或无远程 tracker。目标不确定时停止并询问，不猜平台。一次流程始终使用同一 tracker，不跨平台回退。

完成条件：已记录唯一目标及可用的只读/写入能力。

### 3. 只读查重

在目标 tracker 使用其已验证工具查询相似的 open/closed issue。GitHub 使用 `gh`，GitLab 使用 `glab`；Jira 仅使用仓库已配置且认证可用的 Jira 工具。查重失败时停止，不创建；命中时返回 URL/编号并停止。

完成条件：找到既有 issue，或有证据确认查重未命中。

### 4. 展示并确认外部写入

查重未命中后，向用户完整展示：

- 目标 tracker 与仓库/项目
- 标题
- 完整正文
- 将执行的创建操作

必须在展示之后取得针对本次内容的明确确认。确认前不调用任何远程创建命令；修改标题、正文或目标后必须重新展示并确认。

完成条件：用户明确确认当前展示版本，或流程无写入地停止。

### 5. 创建或降级

- GitHub：确认后使用已认证的 `gh issue create`。
- GitLab：确认后使用已认证的 `glab issue create`。
- Jira：仅在可靠工具与认证均已验证时创建。
- Jira 工具不可用或无远程 tracker：写 `docs/issues/<slug>.md` 本地草稿，标明目标与“未提交”；不得改用其他平台。

创建失败时报告原始失败出口，不重试到其他 tracker，不声称成功。成功时返回同一 tracker 的 URL/编号；本地降级时返回草稿路径并明确“未创建远程 issue”。

## 完成标准

- [ ] 用户明确提出建单意图。
- [ ] 报告只含已验证现象，秘密已脱敏。
- [ ] 在唯一 tracker 完成只读查重。
- [ ] 远程创建前已展示目标、标题、完整正文并取得确认。
- [ ] 最终返回 URL/编号，或明确标注未提交的本地草稿/失败原因。

除非用户随后明确要求查根因或修复，不进入 `/4-debug`。
